# Experimental river rapids implementation plan

**Goal:** Add opt-in flowing shallow rapids with interacting currents, hydraulic jumps,
surface return circulation, sheared foam and existing pastel optics, controlled by `--rapids` and `f`.

**Architecture:** A persistent conservative 2-D shallow-water finite-volume solver uses a
fixed physical grid independent of the terminal, positive depth, hydrostatic reconstruction,
CFL substeps and open channel boundaries over a broad sill and submerged obstruction.
Foam is a transported surface material; the jump's vertical roller is an explicitly empirical
surface closure, not resolved 3-D turbulence. Classic dispersive waves remain the default.
Actual shallow depths feed refraction/absorption/caustics in this mode. Smooth mode changes
blend geometry and material attributes. Software stack: Rust 2024, existing ndarray/crossterm,
no new runtime dependency.

The user clarified that river backflow and boiling are wanted rather than an overturning
surfing tube, and suggested an experimental flag. A shallow hydraulic solver is appropriate
for this separate mode; replacing the original 0.70 m-depth dispersion with shallow-water
equations at the original 2 m patch would have the wrong phase speed. Full 3-D two-phase
fluid simulation exceeds the CPU terminal budget. Independent animated vortex formulas
would not provide the requested fluid interaction.

1. Preserve exact accepted source/native binary under `benchmarks/rapids-before`.
2. Implement and independently test `src/rapids.rs`: lake-at-rest balance, positive depth,
   boundary flux/mass accounting, fixed-tick partition invariance, transported foam bounds,
   developed jump and return-flow indicators, bounded rain impulses.
3. Add persistent mode and same-layout depth/foam buffers to `src/water.rs`. Test resize,
   pause, transition continuity and persistence. All default water invariants remain.
4. Add `--rapids`, `f`, status and complete help state in CLI/input/main/help. Headless
   snapshots and benchmarks honor the flag; warmup genuinely advances the new solver.
5. In `src/term.rs`, use actual water-column depth and conservative foam coverage mixing;
   cache diffuse environment lighting per frame. Preserve the classic path and parallel determinism.
6. Run cargo check before Rust execution, focused numerical tests, then full tests/Clippy/fmt.
   Build a native release and exercise new controls/resize/pause in a real PTY.
7. Inspect developed flow diagnostics and long enough matching-clock previews/motion.
   Save sequential baseline/default/rapids timings, raw samples and source fingerprints.
8. Document solver equations, physical dimensions, boundary conditions, numerical dissipation,
   empirical roller/foam limits and launch controls. Leave the existing working tree reviewable.
